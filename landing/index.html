How it works

From install to a working agent team in three steps.

No new AI accounts and no keys to paste — Devdy builds on the logins and tools you already use.

  1. 1Sign in

    Keep the logins you already have

    Devdy drives the claude and codex CLIs you're already signed in to — your Claude subscription and your ChatGPT account.

    $ claude ✓ Claude subscription $ codex ✓ ChatGPT login ai_api_key — none —
  2. 2Set up

    Add projects, link accounts

    Point Devdy at a folder and it detects the repos inside. Link the GitHub, GitLab or AWS account each project should use, then apply your Skills, Rules and MCP servers.

    demo-app/ ├ github → work ├ skills → claude + codex └ mcp → enabled
  3. 3Delegate

    Hand over a goal

    Fetch an issue or PR, or just describe what you want. The session plans, spawns workers when the job is big, and stops for you at the decisions that matter.

    goal Ship checkout v2 → spawn implementer · reviewer · qa ⏸ waiting for your approval

Multi-agent orchestration

Give one goal. Conductor runs the team.

Every session can act as a conductor: it splits a big task into roles — implementer, reviewer, QA — spawns worker sessions to run them in parallel, reads their results and iterates until the goal is met. You only step in at the checkpoints that matter.

Built for long runs

Hands-off, but never out of control

Conductor keeps going on its own and comes back to you only when a decision is genuinely yours.

  • Auto-resume. The conductor wakes up the moment a worker finishes — no polling, no babysitting.
  • Scales up. 10 parallel workers by default, adjustable up to 100, mixing Claude and Codex.
  • Clear permissions. Every approval window shows which worker is asking, and lost prompts are recovered.
  • Open in place. Jump into any worker, read its transcript or send it a follow-up while the panel stays live.
All in one app

Manage AI context for every project.

Skills, Rules and MCP servers live in one central library, applied to each project — Devdy flags it whenever a project's copy drifts. Then put that context to work on issues, PRs and open-ended sessions.

01 · Skill · Rule

Write once, sync everywhere

Write a Skill or Rule once (or group them), target Claude, Codex or both, then apply it to many projects. Edit the source and projects sync; if a project's copy was hand-edited, Devdy raises a conflict so you choose: use the source, keep local, or write a custom version.

.claude/.codex/AGENTS.md
02 · MCP servers

One MCP library, enabled per project

Define a server once, test it with a real MCP handshake, then switch it on per project — Devdy wires it into that project's runs. Env and header secrets stay in the Keychain; definitions import and export as JSON. SSE servers are Claude-only; Codex runs use stdio and HTTP.

stdioHTTPSSE · Claudetest connection
03 · Analyze issue

Issue → detailed plan

Paste an issue number or URL — GitHub or GitLab. Devdy pulls the content and discussion (skipping bots), then turns it into a detailed plan that follows the Skills and Rules applied to the project.

04 · Review PR / MR

Review PRs and MRs

Fetch a GitHub PR or GitLab MR by number or URL. Devdy gathers the diff and existing reviews — plus the linked issue on GitHub — and reviews it by your conventions.

05 · Free session

Open-ended work sessions

Chat across turns inside a project: @mention files, drop in any file or image, attach notes and todos, reuse saved prompts, jump between prompts in long sessions and resume finished ones.

06 · Permission center

Approve with full context

See a diff before an Edit or Write lands, answer the agent's multiple-choice questions, review its plan before it starts, and pop prompts out into their own window. Choose the mode per run — ask (default), auto-accept edits, plan-only or bypass — and save "always allow" decisions per project.

diff previewAskUserQuestionplan reviewpop-out
07 · Stats

Token & cost stats

Tokens and cost by engine, project, model (subagents included) and day, plus real plan usage for each Claude account and your Codex plan. Deleting old runs never loses the numbers.

Multi-account & usage guard

Every account you own. The right one for every project.

Add as many Claude, GitHub, GitLab, AWS and Google accounts as you need and link them per project — work repos use the work account, side projects use yours. Devdy spreads Claude usage across your logins and stops new runs before you hit your plan limit.

Usage budget

Never blow through your plan limit

Set block thresholds on your real subscription windows — Claude's rolling 5-hour and weekly windows; Codex usually reports only the weekly one. GitHub · GitLab

Multiple GitHub and GitLab (self-hosted too) accounts, scopes validated. Each project's runs use only its linked account for gh, glab and git — your global login is never touched.

AWS

Menu bar, pop-outs & notifications

Devdy stays out of the way until you need it.

  • Menu-bar switcher. See the running-session count and jump to any running session from the tray.
  • Pop-out windows. Sessions, todos, notes and permission prompts each in their own window.
  • Native notifications. Know when a background session finishes or needs your approval.
  • Make it yours. Light / dark themes, seasonal scenes, an English / Vietnamese UI and an optional Cyber Fox mascot.
Local-first & privacy

Everything Devdy stores stays on your machine.

  • No AI API keys. Claude and Codex authenticate with your existing claude / codex CLI logins.
  • Secrets stay in the Keychain. GitHub/GitLab tokens, MCP credentials, Google logins and server passphrases live only in the OS Keychain — never in a file, a log or the engine's environment.
  • Per-run credential broker. Each run gets tokens only for the account linked to its project, on request, through a policy, approval and audit layer — and fails closed instead of falling back to your global login.
  • No Devdy cloud. Skills, rules, history and stats live in local SQLite and log files. Your prompts go to the engine you run (Anthropic or OpenAI), connected services such as GitHub or Google talk to their own APIs, and remote control goes through your own end-to-end encrypted relay.
  • You choose the permission mode. By default Devdy asks before sensitive tool calls; per run you can switch to auto-accept edits, plan-only or bypass.
